# 要件定義書 — 一人暮らし新生活 総合最適化ナビ

吉川徹財団 第4期奨学生 応募ポートフォリオ用プロジェクト（締切: 2026-10-18）

## 1. 背景・目的

一人暮らしを始めた大学生は「収入（バイト・扶養の壁）」と「支出（固定費・経済圏）」を
別々に、かつ勘と経験だけで管理しがちで、最適化の機会を逃しやすい。

本アプリは、開発者自身が2026年3月の一人暮らし開始後に実際に直面した2つの課題

- 複数バイト（CAZAN珈琲店＋VEXUM）の掛け持ちシフトと扶養の壁のバランス管理
- 銀行・カード・証券・通信キャリアの「経済圏」の非効率（ゆうちょ経由NISAの高信託報酬など）

を、自身の実体験に基づいたロジックで解決するツールとして設計する。

## 2. ターゲットユーザー

- 一人暮らしを始めた/始める大学生（特に複数のアルバイトを掛け持ちする学生）
- 特定扶養控除（19〜23歳）の対象で、「稼ぎすぎ」による親の控除縮小を避けたい人
- 楽天経済圏・PayPay経済圏など、決済/通信/証券をまとめて最適化したい人

## 3. 競合・類似サービス調査と差別化

| サービス | 強み | 弱み・本プロジェクトとの違い |
|---|---|---|
| [パート・アルバイト手取り計算ツール](https://tedori-calc.pages.dev/) | 106/130/178/201万の壁判定、年間シフトシミュレーターが充実 | 単一バイト前提。経済圏診断なし |
| [扶養範囲内計算シミュレーター](https://ikigai.town/ja/yougo/fuyou-keisan.html) | 表形式で年収帯別の壁を即判定 | 配偶者控除中心（既婚者向け）、学生の複数バイトは想定外 |
| [扶養の壁カウンター(アプリ)](https://play.google.com/store/apps/details?id=com.ototo.watasiha.fuyonokabecounter) | 壁を自由設定できるカウンター | 単発の年収管理のみ、シミュレーションや診断機能はない |
| マネーフォワードME等の家計簿アプリ | 口座連携、サブスク可視化 | 汎用的で「学生×扶養の壁×経済圏」に特化した診断ロジックはない |
| [クレカ診断アプリ](https://credit-card-simulator-two.vercel.app/) | カード×決済ルート診断、カジュアルなUI | カード最適化のみ。収入側（バイト・扶養）とは無関係 |

**差別化ポイント**
1. **複数バイト横断の最適化**: 既存ツールはほぼ単一バイト前提。実際の時給差（1160→1190円 / 1300円）を持つ2つのバイトを横断してシフト配分を最適化する視点は competitors にない
2. **収入最適化×支出最適化の統合**: 「壁」計算と「経済圏診断」を1つのダッシュボードで扱うツールは見当たらなかった
3. **実体験に基づくロジック**: 楽天経済圏棚卸し（信託報酬比較、ポイント通帳の実務的な落とし穴など）を一般化したロジックとして実装し、実体験の裏付けがある

## 4. 機能要件

### 4.1 モジュール1: マルチジョブ扶養最適化シミュレーター

**入力**
- バイト情報（複数登録可）: バイト名、時給、週の勤務日数、1日の勤務時間
- 家族情報: 特定扶養控除の対象か（19〜23歳）、社会保険上の扶養に入っているか
- 開始月・シミュレーション対象年度

**処理ロジック**
- 各バイトの月間給与を合算し、年間見込み収入を算出（給料とおこづかいを分離する考え方 = 本人の家計簿分析で得た知見を反映し、「入力するのは給料のみ」と明示）
- 123万円の壁（所得税・住民税、2025年改正後）・130万円の壁（社会保険）に対する残り稼働可能額を月別に逆算
- 壁到達が見込まれる月をタイムラインで警告表示

**出力**
- 年間収入見込みのプログレスバー（2本の壁それぞれに対して）
- 「あと月◯時間まで働けます」という残り稼働可能時間の表示
- 壁を超えそうな場合、どのバイトのシフトを何時間減らせば回避できるかの提案

### 4.2 モジュール2: 経済圏・固定費最適化診断

**入力**
- 現在契約中の銀行、クレジットカード/デビットカード、通信キャリア、NISA運用先（選択式）
- 月々の固定費（サブスク等）の一覧（任意入力、複数追加可）

**処理ロジック**
- 各カテゴリごとに「ポイント還元率」「信託報酬」「セット割引」等の代表的な差分をルールベースで比較
- 現状の組み合わせと、最適化した場合の年間の差額（円）を試算

**出力**
- カテゴリ別診断結果カード（現状 vs 推奨、年間差額）
- 総合の年間節約ポテンシャル額

### 4.3 モジュール3: 統合サマリーダッシュボード

- モジュール1・2の結果を1画面に集約
- 月次の手取り収支見込み（収入シミュレーション − 固定費診断後の支出）をグラフ表示
- 3枚のKPIカード: 「壁までの余裕」「経済圏最適化ポテンシャル」「月間手取り見込み」

## 5. データ方針

- **本人の家計簿・バイト時給などの個人データ**: 本人確認済みのため、初期値（デモ用プリセット）として実数値を使用可
- **家族の年収など第三者に関わる情報**: 実数値は使わず、**総務省家計調査（単身世帯・34歳以下の平均支出 月17.3万円、2025年）**や**JASSO学生生活調査**など公的統計の平均値をデフォルト値として採用し、出典を明記する。ユーザーは自分の値に自由に上書きできる
- すべての入力はブラウザのstate内で完結させ、サーバーに送信・保存しない（プライバシー配慮を明示し、README/UI上でも「入力データはサーバーに送信されません」と明記）

## 7. 画面構成

1. `/` トップ（プロダクト説明、開発の背景ストーリー）
2. `/simulator` マルチジョブ扶養シミュレーター
3. `/economic-zone` 経済圏診断
4. `/dashboard` 統合サマリー

## 8. 非機能要件

- レスポンシブ対応（スマホ優先、本人はPCよりスマホ利用が多い）
- ダーク/ライトモード両対応
- Lighthouse スコアを意識したパフォーマンス（画像最適化、不要な依存排除）

## 9. 技術スタック

- Next.js (App Router) + TypeScript + Tailwind CSS
- 状態管理はReact標準のuseState/useReducerで完結（外部ライブラリ最小限）
- グラフ描画は軽量ライブラリ（Recharts想定）
- デプロイ: Vercel（GitHub連携で自動デプロイ）
